# 오답노트 (문제별 실수 + 배운 개념)

> 시험 전날 이 파일만 훑어도 그날그날 막혔던 포인트가 떠오르게. 각 항목은 치트시트(`00_CPP_치트시트.md`)의 해당 섹션과 연결됨.

---

## 1. 키패드 누르기 (67256) — `1_키패드_누르기.cc`

**유형:** 구현 + pair 좌표 계산

**그때 막혔던 것 / 실수:**
- `pair<3,0>` 처럼 **값을 `<>`(타입 자리)에** 넣으려 함 → `pair<int,int> p = {3,0};` 가 맞음. `<>`는 항상 타입, 값은 `{}`. (→ 치트시트 2-3)
- `if (...):{ }` 처럼 파이썬 콜론 습관이 나옴 → C++는 `if(...) { }`, 콜론 없음
- `answer += 'L'` 세미콜론 빠뜨림

**배운 개념:** `pair<int,int>`, `.first`/`.second`, 정수 나눗셈(`/`, `%`)으로 좌표(행,열) 계산, `vector<vector<int>>` vs `vector<pair<int,int>>` 차이

## 2. 게임 맵 최단거리 (1844, BFS) — `27_게임_맵_최단거리.cc`

**유형:** BFS (하이닉스 출제 근거는 약함, 보험용으로 학습)

**그때 막혔던 것 / 실수:** 특별히 없음, 한번에 통과. 스타일 팁: `answer` 변수에 루프마다 갱신하는 대신, 루프 끝나고 `return dist[n-1][m-1];` 한 번이 더 깔끔함 (버그는 아님).

**배운 개념:**
- `queue<pair<int,int>>` — 왜 BFS엔 vector 대신 queue를 쓰는지 (vector로 맨 앞 제거하면 O(n), queue는 O(1))
- BFS 원리: "물결처럼 퍼짐" → 처음 도착한 순간이 곧 최단거리
- `dist` 배열 하나로 방문체크+거리기록 겸용 (`-1` = 미방문)
- `vector<vector<int>> dist(n, vector<int>(m, -1));` 이 왜 n행 m열로 채워지는지 (→ 치트시트 2-1, "왜 저렇게 생겼는지")

## 3. 크레인 인형뽑기 게임 (64061) — `3_크레인_인형뽑기_게임.cc`

**유형:** 구현 + 스택

**그때 막혔던 것 / 실수 (제일 많았던 문제):**
- `cout >> p >> endl;` → `<<`가 아니라 `>>`를 써서 컴파일 에러. **출력은 `<<`, 입력(`cin`)은 `>>`.**
- `for (vector v : board)` (참조 `&` 없이) → `v[n]=0` 해도 `board` 원본이 안 바뀜. `for (vector<int>& v : board)`로 고쳐야 원본이 실제로 바뀜. (→ 치트시트 2-1a)
  - 처음엔 "파이썬에서 반복 중 리스트 바꾸면 에러났던 것"이랑 헷갈렸는데, 그건 **원소 개수(구조)를 바꿀 때**(`RuntimeError`/`IndexError`) 나는 에러고, 지금은 **이미 있는 값만 바꾸는 것**이라 완전 다른 얘기였음.
- `break` 없어서 한 열에서 **하나만** 뽑아야 하는데 끝까지 다 뽑아버릴 뻔함 → 첫 번째로 찾은 칸 처리하고 바로 `break`.

**배운 개념:**
- `stack<int>` — `push`/`top`/`pop`, LIFO
- "방금 넣은 것 vs 그 아래 것" 비교 패턴 (→ 치트시트 2-6)
- 참조(`&`)가 뭔지: 포인터 아니고 "원본의 별명". `int& d = c;`면 `d`랑 `c`는 같은 상자.
- `find()`가 반환하는 게 bool도 인덱스도 아니고 **iterator(위치, 화살표)**라는 것, `!= end()`로 비교해야 bool이 나옴 (→ 치트시트 2-1)

## 5. 피로도 (87946) — `15_피로도.cc`

**유형:** 완전탐색 / 순열

**그때 막혔던 것 / 실수:** 없음, 한번에 정답. (검증 중 내가 직접 만든 엣지케이스 기대값을 잘못 계산했었음 — `[5,1]` 던전은 한 번 들어가면 체력이 5→4가 되어 같은 던전을 또 못 들어간다는 걸 놓쳤던 것. 코드는 처음부터 맞았음.)

**배운 개념:**
- `next_permutation` 쓰는 법 — `#include <algorithm>`, 반드시 `sort` 먼저, `do-while`로 감싸기 (→ 치트시트 3장)
- 값이 같은 원소가 있으면 `next_permutation`이 중복 순열을 자동으로 건너뜀
- **바깥 루프(순열 바꾸기, do-while)랑 안쪽 루프(한 순서로 쭉 시뮬레이션, for)는 서로 다른 루프** — 헷갈리지 않기
- 입장 실패해도 **멈추지 않고 다음 원소로 계속 진행**하는 패턴 (하나 막혔다고 전체를 포기하지 않음)

## 4. 모의고사 (42840) — `12_모의고사.cc`

**유형:** 완전탐색 / 패턴 비교

**그때 막혔던 것 / 실수:** 특별히 없음, 공식 예제 2개 한번에 통과.

**배운 개념:**
- `i % pattern.size()`로 짧은 패턴을 계속 반복시키는 법 (→ 치트시트 1장, "%로 패턴 순환시키기")
- `max_element`는 값이 아니라 **위치(iterator)**를 준다 → `*` 붙여야 값. `max(a,b)`(값 2개 비교, 값 그대로 반환)랑 헷갈리지 말 것.
- `max_element`/`find`는 조건에 맞는 것 중 **제일 처음 것 하나만** 찾는다 — 공동 1등처럼 여러 개 다 찾아야 하면, 최댓값만 구하고 **직접 for문으로 전부** 수집해야 함. (→ 치트시트 3장)

## 5. 소수 찾기 (42839) / 카펫 (42842) — 다른 컴에서 작업, `13_소수_찾기.cc` / `14_카펫.cc`

**유형:** 완전탐색 (순열 / 약수 관계)

**참고:** 이 둘은 다른 컴퓨터에서 미리 풀어온 것이라 실시간으로 겪은 실수 기록은 없음. 컴파일+공식 예제 검증만 완료 (둘 다 정답).

**짚어둘 것:** 소수 찾기는 `next_permutation` + 소수 판별(`j*j <= num`이 `j <= num`보다 빠름, 지금 범위(최대 7자리)에선 둘 다 통과하지만 더 큰 범위 문제 만나면 제곱근 방식 쓸 것). (→ 치트시트 3장, next_permutation)

## 기타 — 문제와 무관하게 물어봤던 개념 (치트시트에 반영됨)

- `vector<int, int>` 안 됨 (allocator 자리라 값 못 넣음) → `pair<int,int>` 써야 함
- `erase(v.begin()+i)` — 인덱스 대신 iterator(화살표) 위치로 지정
- `count`가 vector에서 쓰이면 "개수", map/set에서 쓰이면 "있는지(0/1)" — 같은 이름, 다른 의미
- 파이썬 슬라이싱(`arr[-1]`, `arr[a:b]`)은 C++에 없음, `v.back()`/`vector<int> sub(begin+a, begin+b)`로 흉내
